# Parity rows, MY: Multi yard platform

The detail behind the [MY rows of the parity matrix](../LBM-PARITY-MATRIX.md#my-multi-yard-platform). R, B and A refs link the Rundoo, BisTrack and Agility pages each claim rests on; Gable's evidence links its code on `refactor/v1` at `695d587c`.

## MY-01

**Branch level security (users and roles held to branches).** Priority **MUST**: Multi yard security on by default for a multi yard dealer, grants managed on screen.

- **Rundoo** (Yes, documented): 47 per person permissions in seven sections plus manager PIN or login key gates; staff access is location scoped. Multi yard: A clerk granted one location does not see another's inventory or sales; a separate permission allows switching the signed in location. [R21](https://www.rundocs.com/help/admin-settings/permissions/) [R20](https://www.rundocs.com/help/admin-settings/locations/) [R12](https://rundoo.ai/product/run-on-a-stable-secure-private-platform/) [R23](https://www.rundocs.com/help/admin-settings/pos-security/) [R22](https://www.rundocs.com/help/admin-settings/staff/)
- **BisTrack** (Partial, documented): User permissions are grouped and can differ between WMS enabled and other branches; BisTrack Web user profiles control menus; Epicor Identity adds single sign on and two factor. Holding users to specific branches is not described. Multi yard: Permissions vary by branch type, not documented per branch. [B69](https://www.mydoitbest.com/wp-content/uploads/2024/02/Whats-New-in-BisTrack-2023.2.pdf) [B30](https://www.epicor.com/en-us/products/enterprise-resource-planning-erp/bistrack/bistrack-web-and-epicor-identity/) [B33](https://www.epicor.com/en-us/blog/technology-and-data/introducing-bistrack-web/)
- **Agility** (Yes, documented): Organization security assigns roles per branch by position in an org hierarchy (branch, region, company); action and data allocations limit cross branch views such as A/R for all branches. Multi yard: Core multi yard security. [A119](https://documentation.dmsi.com/Agility/prod/System_Administration/organizationsecurity.htm) [A27](https://restdoc.dmsi.com/) [A120](https://documentation.dmsi.com/Agility/prod/System_Administration/securitydataallocation.htm)
- **The MVP** (Partial, master): Migrations 058-060, pkg/middleware/branch.go:118 (middleware_test.go, branch_isolation_test.go), and location/handler.go:53-70 provide branch CRUD, user_locations grants, X-Branch-Id context, and branchSelector.ts. However, multi_branch_enabled defaults to false (branch.go:259), omitted X-Branch-Id reads all branches for admins, and inventory/GL/AP/payments/routes lack branch_id.
- **Gable today** (Partial): `user_locations` branch grants and `core/pkg/middleware/branch.go` validate `X-Branch-ID`, compute `middleware.Wall` across granted branches when no header is sent, and wall POS, orders, POs, AP, quotes, CRM, accounts, exposure, reporting, scheduled reports, and dashboard; 9 personas seeded. **Missing:** Some endpoints (such as delivery routes and GL statements) have no `branch_id` column and remain dealer-wide.
