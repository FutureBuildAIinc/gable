# Parity rows, IX: Integrations

The detail behind the [IX rows of the parity matrix](../LBM-PARITY-MATRIX.md#ix-integrations). R, B and A refs link the Rundoo, BisTrack and Agility pages each claim rests on; Gable's evidence links its code on `refactor/v1` at `695d587c`.

## IX-01

**Payment processors and card terminals.** Priority **MUST**: The card terminal and gateway seams (with CP-05 and PE-02).

- **Rundoo** (Partial, documented): Integrated Stripe card and ACH processing with Stripe Terminal readers (such as WisePOS E) assigned per location; no other processor can be connected. Multi yard: Each Stripe reader is paired and assigned to a location. Add on or partner: Stripe (required). [R81](https://www.rundocs.com/help/integrations/stripe/) [R4](https://rundoo.ai/pricing/)
- **BisTrack** (Yes, marketing only): Epicor Payment Exchange and gateway integrate with BisTrack in the US and Canada; the Epicor Payment Application runs in the cloud; Shift4 integration covers EMV terminals. Add on or partner: Epicor Payments (optional module); Shift4 (partner). [B51](https://www.epicor.com/en-us/products/digital-commerce/payments/payment-exchange/) [B63](https://www.epicor.com/en/products/digital-commerce/payments) [B32](https://www.epicor.com/en-us/blog/industries/bistrack-2024-2-empowering-your-business-with-enhanced-functionality/) [B64](https://shift4.com/news/shift4-and-epicor-software-provide-emv-to-lumber-and-building-materials-dealers-and-distributors)
- **Agility** (Yes, documented): Worldpay with triPOS for EMV, stored cards, surcharges, Level II and III and a hosted payment page for eCommerce; Billtrust for invoice delivery and payments. Add on or partner: Credit Card Interface (Worldpay card product); Billtrust Interface. [A34](https://documentation.dmsi.com/Agility/prod/Integrated_Solutions/creditcardinterface.htm) [A36](https://documentation.dmsi.com/Agility/prod/Integrated_Solutions/creditcardsurchargefees.htm) [A27](https://restdoc.dmsi.com/) [A131](https://documentation.dmsi.com/Agility/prod/Integrated_Solutions/billtrustinterface.htm)
- **The MVP** (Partial, its staging line): staging adds RunPaymentsGateway (payment/run_payments.go:38, run_payments_test.go) for card-not-present charge, void/refund, JWT key refresh, AES-256-GCM vault cipher (vault.go:25, vault_test.go), DB keystore (keystore.go:18), routes (handler.go:30-36), and RunPaymentsForm.ts. No EMV terminal rail, saved card-on-file table, ACH, or payment links.
- **Gable today** (Partial): Online card and ACH payments run through `RunPaymentsGateway` (`core/internal/payment/gateway.go`), while counter POS card tenders use a separate terminal path with refund payback claim locks (`110_refund_intent_payback.sql`, `111_payback_one_per_tender.sql`). **Missing:** No physical EMV/tap card-present terminal driver (e.g. Stripe Terminal, Adyen, Pax, or Verifone) is wired in `serve.go` (`pos.Service` runs with a nil terminal gateway unless injected in tests). Evidence: [`core/internal/payment/gateway.go:18`](https://github.com/FutureBuildAIinc/gable/blob/695d587c5d7431194005a93bec51deb53c3e2749/core/internal/payment/gateway.go#L18), [`core/internal/pos/complete.go:228`](https://github.com/FutureBuildAIinc/gable/blob/695d587c5d7431194005a93bec51deb53c3e2749/core/internal/pos/complete.go#L228), [`core/internal/pos/service.go:165`](https://github.com/FutureBuildAIinc/gable/blob/695d587c5d7431194005a93bec51deb53c3e2749/core/internal/pos/service.go#L165), [`core/migrations/110_refund_intent_payback.sql:1`](https://github.com/FutureBuildAIinc/gable/blob/695d587c5d7431194005a93bec51deb53c3e2749/core/migrations/110_refund_intent_payback.sql#L1).
